## 1. 系统定位

- 本系统是**门诊预约与分诊协作的辅助系统**，不是分诊诊断系统。改善的业务结果是：迟到患者与现场加号混队导致的候诊等待延长（中位数 68 分钟 → 目标 40 分钟，f00）、护士每日约 180 次次序解释的重复劳动（f12/f51）、以及次序争议引发的投诉风险。
- 系统只做三类事：**时间解释**（三套等待口径的透明展示）、**队列信息辅助**（谁迟到、谁加号、该排哪）、**异常提示与暂停**（排班未同步等异常时提示并暂停建议，f11/f15）。
- 系统不做的事：不自动改队列次序、不做分诊诊断、不调整医嘱、不对外承诺结果。所有"最终放行"由对应岗位人工确认（f15/f22/f52）。

## 2. 用户与权限（RBAC）

六个角色，权限矩阵按访谈事实硬约束设计：

| 角色 | 代码标识 | 可做 | 不可做 | 依据 |
|---|---|---|---|---|
| 导诊护士 | `nurse` | 查看队列辅助建议、暂存草稿、发起转人工、确认放行 | 改队列排序、看未授权数据 | f10/f13/f15 |
| 排班管理员 | `scheduler` | 整理校核、发起复核、核对异常、分派异常 | 代替质控签核、批准辅助范围外操作 | f22/f25/f24 |
| 门诊运营主任 | `director` | 定范围/停止、确认基线口径、验收 | —— | f03/f04/f05 |
| 门诊系统工程师 | `engineer` | 维护只读接口、数据校验、修复队列管理 | 写业务数据 | f30/f32/f33 |
| 患者服务主管 | `service` | 受理争议、参与服务结果验收 | 未经确认对外承诺 | f52/f54 |
| 医疗质控专员 | `qc` | 审计查询、否决上线、复核留存 | —— | f04/f41/f43/f45 |

权限硬规则：禁止借用账号（f41）；只有授权岗位可看号源、排班、签到叫号时间与分诊规则（f41）。

## 3. 技术栈【待确认——需求方未给出，以下为默认建议，确认后冻结不许换】

- **语言/运行时**：Python 3.11
- **Web 框架**：FastAPI + uvicorn
- **多智能体编排**：LangGraph（状态图编排，不用其他 Agent 框架）
- **模型接入**：OpenAI 兼容接口（base_url / api_key / model 全部走 config.yaml，不写死在代码里）
- **数据库**：SQLite（试点阶段单机，通过 SQLAlchemy 访问；不引入 Redis/MQ 等任何中间件）
- **配置**：PyYAML，全部配置集中 `config.yaml`
- **测试**：pytest + httpx
- **返回结构**：所有对外接口统一 `{"ok": bool, "data": ..., "error": {"code": str, "msg": str}}`

## 4. 多智能体设计（LangGraph 状态图）

```
用户请求 → 安全审查网关（权限校验 + 敏感词/越权意图拦截）
        → 路由节点（按意图分发）
   ├─ 队列信息智能体：回答"当前队列谁迟到/谁加号/排在哪"，输出必须附带原记录与待确认字段（f15）
   ├─ 时间解释智能体：按固定口径解释等待时间，标注口径来源与最后同步时间（f53/f34/f13）
   ├─ 异常检测智能体：识别排班未同步等异常 → 输出"暂停建议"，进入人工修复队列（f11/f15/f33）
   └─ 转人工协调智能体：急症/缺依据/版本冲突/系统不可用 → 转人工，必须标注触发原因+接手人+确认时间（f44）
        → 人工确认节点（写操作全部止步于此，人工确认后才生效）
        → 审计留痕节点（每次建议落审计表，f45 字段）
```

智能体职责边界：每个智能体只读自己权限内的数据；写操作（改队、放行、承诺）不进任何智能体，只进人工确认节点。

## 5. 数据模型（核心表）

- `users`：账号、角色、所属岗位（不支持账号借用，登录绑定角色）
- `queue_records`：队列记录（业务编号、患者脱敏编号、来源类型[预约/迟到/加号]、状态、版本、最后同步时间）
- `schedule_snapshots`：排班只读快照（带时间戳，f34/f35：每天两次更新、中断时用上一份快照并显示"暂未更新"）
- `audit_logs`：审计留痕（业务编号、资料版本、事实引用、建议结果、人工改动、签核人，f45）
- `manual_handoffs`：转人工记录（触发原因、接手人、确认时间，f44）
- `repair_queue`：歧义数据人工修复队列（f33，不进自动推荐样本）

数据红线落地：患者姓名/证件等隐私字段不入库不入模型输入，只存脱敏编号。

## 6. 数据红线（硬约束，代码中逐条卡点）

1. **只读**：对排班与队列只读，无任何写接口直连业务系统（f32）。
2. **临床优先级**：急症症状识别 → 必须转人工，预约顺序永不置于临床优先级之上（f40/f42）。
3. **急症全转人工**：急症识别提示 100% 转人工，作为验收硬线（f02/f42）。
4. **错误不覆盖**：异常场景下建议暂停，错误结果不得覆盖原记录（f15）。
5. **人工确认**：最终放行、次序调整、对外承诺必须对应审批人确认（f22/f41/f54）。
6. **转人工留痕**：触发原因、接手人、确认时间三字段强制（f44）。
7. **审计可重建**：每次建议保留 f45 六字段，可重建处理链；不记录口令与不必要个人信息。
8. **留存 90 天**：评价记录暂留 90 天，期满由质控复核删除或归档（f43）。

## 7. 接口规范（统一返回结构）

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/auth/login` | POST | 登录，发 token（绑定角色） |
| `/api/queue/query` | GET | 队列信息辅助查询（带口径标注与同步时间） |
| `/api/queue/explain` | POST | 时间解释（三口径对照） |
| `/api/anomaly/check` | POST | 异常检测（返回暂停建议+原记录+待确认字段） |
| `/api/handoff/create` | POST | 发起转人工 |
| `/api/handoff/confirm` | POST | 接手人确认（f23：对方确认才算交接完成） |
| `/api/audit/list` | GET | 审计查询（仅 qc/director） |
| `/api/repair/list` | GET/POST | 人工修复队列（仅 engineer/scheduler） |

错误码规范：`AUTH_XXX`（权限）、`REDLINE_XXX`（红线拦截）、`DATA_XXX`（数据校验）、`SYS_XXX`（系统）。

## 8. 代码规范

- 每个函数写中文 docstring：入参、出参、失败时的行为。
- 安全审查、权限校验、人工确认三处关键业务逻辑必须写中文行内注释，说明为什么这么卡。
- 配置统一 `config.yaml`；密钥、模型地址禁止写死在代码里。
- 每行代码添加中文注释。
